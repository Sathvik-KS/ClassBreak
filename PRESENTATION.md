## 1. The 30-second pitch

ClassBreak is a personal learning app for short breaks. You open it, get a feed
of interesting topics, tap one, and read a readable lesson generated by AI but
grounded in real Wikipedia sources. You can then ask the tutor follow-up
questions, take a quiz, save the lesson, and get reminded to review it later
using spaced repetition. It works on the web (installable PWA) and as an
Android-first Expo app.

**The learning loop it implements:**

```
Discover → Understand → Explore Deeper → Remember → Connect
```

- **Discover** — personalized topic feed.
- **Understand** — structured lesson: summary, sections, key points, examples.
- **Explore Deeper** — AI tutor with follow-up suggestions, plus related topics.
- **Remember** — quiz with explanations and a spaced-repetition review schedule.
- **Connect** — sources, related topics, and saved lessons you can revisit.

**The twist:** it is deliberately **guest-first and local-first**. No account,
no signup, no server-side user database. Every piece of personal learning data
stays on the device (IndexedDB on web, AsyncStorage on mobile). The backend is a
stateless AI proxy and source fetcher — nothing about you is stored there.

## 2. Why this project exists (problem → solution)

| Problem | ClassBreak's answer |
|---|---|
| Long courses need commitment you don't have in a 5-minute break | Lessons sized for 2–15 minutes, default 5 |
| Generic AI answers are ungrounded and hard to trust | Wikipedia-grounded prompts, citations labeled by type |
| AI keys are dangerous in client apps | Server-side proxy; clients never see credentials |
| Accounts are friction and a privacy liability | Guest-first, local-first, no accounts |
| Content disappears when you go offline | Saved lessons readable from device storage |
| Learning is forgotten immediately | Quiz + SM-2-lite spaced repetition |

## 3. What the app actually does

### Web client (`frontend/`)

| Screen | Route | Behavior |
|---|---|---|
| Discover | `/` | Calls `POST /api/discover/feed` with preferences, excluded topics, last 20 feed IDs; "Learn this" generates and auto-saves a lesson |
| Lesson | `/lesson/:id` | Reads saved lesson from IndexedDB; renders safe Markdown; key points, examples, takeaways, sources, related topics; quiz/tutor/download/delete actions |
| Quiz | `/quiz/:id` | 5 questions; multiple choice checked locally, open-ended answers evaluated by the backend; feedback, progress, results; attempts persisted |
| Tutor | `/tutor/:id` | Lesson context + last 10 messages to `POST /api/tutor/chat`; Markdown answers and follow-up chips; disabled offline |
| Saved | `/saved` | Live Dexie query; read, toggle offline download, delete |
| Review | `/review` | Due/upcoming lists; "Remembered it" / "Need another pass" advances the schedule |
| Settings | `/settings` | 16 interest chips, default duration (2/5/10 min), live backend health + provider, privacy note |

### Mobile app (`mobile/`, Expo SDK 58)

| Route | Purpose |
|---|---|
| `(tabs)/index` | Discover feed (10 items), pull-to-refresh, retry/empty states |
| `(tabs)/saved` | Saved lessons from AsyncStorage |
| `(tabs)/review` | Due/upcoming spaced-repetition list |
| `lesson/[topic]` | Generate and read a lesson |
| `saved/[id]` | Read a saved lesson with **no API call** |
| `quiz` | 5-question quiz, pass threshold 0.6 |
| `tutor` | Tutor chat; lesson passed as a JSON route param |

Mobile differences (intentional): no Settings screen, no interest preferences,
no feed history/exclusions, no related-topic chips, and lessons are saved on tap
(or when a quiz finishes) rather than automatically.

### Backend (`backend/`)

A stateless FastAPI service exposing 7 routes. It fetches Wikipedia material,
builds prompts, calls the configured AI provider, validates the response shape,
structurally validates citations, and returns JSON. It stores nothing.

## 4. Architecture at a glance

```
┌──────────────────────────────┐
│  Web (React 19 + Vite PWA)   │  IndexedDB (Dexie)
│  mobile-first, installable   │
└──────────────┬───────────────┘
               │ JSON over HTTP
┌──────────────┴───────────────┐
│  Mobile (Expo SDK 58 / RN)   │  AsyncStorage
│  Android-first, Expo Go      │
└──────────────┬───────────────┘
               │  (native bypasses browser CORS)
               ▼
      ┌──────────────────┐
      │ FastAPI backend  │  stateless · no database · no accounts
      └───┬──────────┬───┘
          │          │
          ▼          ▼
  AIProvider      Wikipedia APIs
  ├ Gemini        ├ REST summary
  └ Mock          ├ MediaWiki opensearch
                  └ MediaWiki extracts
```

Key properties:

- One shared HTTP/JSON contract for both clients.
- AI credentials exist only in backend environment variables.
- Wikipedia grounding is best-effort: failures degrade to fewer sources, never
  a failed lesson request.
- Rate limiting is the only abuse/cost control; it is in-memory and
  per-process.
- There is no database, no migration step, no user table, no cookies, no auth.

## 7. API surface

| Method | Path | Purpose | Limit |
|---|---|---|---|
| GET | `/api/health` | Status, effective provider, version | Exempt |
| POST | `/api/discover/feed` | Generate discovery feed | 30/min |
| POST | `/api/lessons/generate` | Generate a lesson | 30/min |
| POST | `/api/lessons/quiz` | Generate quiz questions | 30/min |
| POST | `/api/lessons/evaluate` | Evaluate an open-ended answer | 30/min |
| POST | `/api/tutor/chat` | Tutor chat turn | 30/min |
| GET | `/api/sources/search?q=...` | Wikipedia source search | 60/min |

- Limits are configurable via `RATE_LIMIT` and `RATE_LIMIT_READ`.
- 429 responses use `{"detail": "...", "Retry-After": ...}`.
- Validation failures are FastAPI's default 422; oversize bodies (header-based,
  >100,000 bytes) are 413; unexpected errors are a generic 500.
- Interactive docs: `http://localhost:8000/docs`.

### Core data shapes (shared by all three codebases)

```text
Lesson          id, title, summary, topic, domain, difficulty,
                duration_minutes, sections[{heading, content, key_points[]}],
                examples[], takeaways[], references[], related_topics[],
                generated_at
Reference       title, url, source_type (wikipedia | provided), extract?
FeedItem        id, title, hook, topic, domain, difficulty, estimated_minutes
QuizQuestion    id, question, options[], correct_answer, explanation,
                question_type (multiple_choice | open_ended)
AnswerEvaluation is_correct, score (0..1), feedback, correct_answer
TutorResponse   answer, follow_up_suggestions[], references[]
SavedLesson     Lesson + savedAt (web also adds isDownloaded)
```

The web and mobile `types/index.ts` files mirror the backend Pydantic models.
When the contract changes, all three must change together.

### How a lesson is produced

1. Client sends topic, duration, depth, optional interests.
2. Backend searches Wikipedia (summary → opensearch → extracts).
3. Source text is formatted into the prompt context.
4. Provider returns raw JSON (`GeminiProvider` or `MockProvider`).
5. Pydantic validates the shape; citations are structurally validated.
6. Client receives `LessonResponse`; web auto-saves it, mobile offers Save.

### AI provider behavior

| Config | Effective provider |
|---|---|
| `AI_PROVIDER=auto` (default) + key | Gemini |
| `AI_PROVIDER=auto`, no key | Mock |
| `AI_PROVIDER=gemini`, no key | Mock (warns at startup) |
| `AI_PROVIDER=mock` | Mock |
| Unknown value | Mock (warns at startup) |

- Gemini: `gemini-3.6-flash`, low thinking level, JSON response mode,
  temperature 0.7 (deprecated and ignored from 3.6 onward),
  `max_output_tokens=8192` (includes thinking tokens), 30 s timeout enforced
  via `asyncio.wait_for`, SDK call offloaded with `asyncio.to_thread`.
- Mock: works with **no credentials** — 12 feed items, one fixed lesson
  (retitled for other topics), 3 fixed quiz questions, keyword-based
  evaluation. Useful for demos and tests; not a showcase of AI quality.
- Wikipedia: 10 s timeout, custom User-Agent, up to 3 sources for lessons and 5
  for source search, related extracts capped at 1,000 chars. Any upstream
  failure degrades to fewer sources instead of erroring.
- Citation validation is **structural only** (valid `http(s)` URL, no
  duplicates). It is not fact-checking. URLs not in the fetched set are labeled
  `provided`, i.e. "model-supplied, unverified".

## 8. Data storage and privacy

| Concern | Web | Mobile |
|---|---|---|
| Store | IndexedDB via Dexie (`classbreak`) | AsyncStorage JSON lists |
| Saved lessons | `lessons` table, auto-saved on generation | `classbreak.savedLessons`, saved on tap/quiz |
| Review schedule | `reviewItems` table | `classbreak.reviewItems` |
| Quiz history | `quizAttempts` table | Not stored |
| Feed history | `feedHistory`, capped at 200 | Not stored |
| Offline reading | Saved lesson + cached app shell | Saved lessons are always local |
| Server-side user data | **None** | **None** |

- Preferences: 16 interests, default duration, theme flag (stored but unused).
- Deleting a lesson also deletes its review items and quiz attempts (web).
- Review scheduling (SM-2-lite): first correct → 1 day, second → 3 days, then
  `interval × easeFactor`; ease +0.1 per correct (min 1.3). Wrong → 1 day and
  ease −0.2 (min 1.3). Web and mobile use the same rules.
- Clearing browser/app data deletes learning history. There is **no export,
  backup, sync, or recovery** yet.
- **Dexie rule:** never index boolean fields. IndexedDB silently excludes
  booleans from indexes; query them with `.filter()` instead.

### Service worker / PWA policy

- Caches only the static app shell and same-origin hashed assets.
- **Never** caches `/api/*`, cross-origin requests, or non-GET requests.
- Navigation: network-first with cached `/index.html` fallback.
- Registered only in production builds.
- Offline: saved lessons still read; discovery/quiz/tutor need the network.

## 9. Setup — Linux and macOS

Prerequisites:

- Python **3.14.x** with `venv` (on Kubuntu/Debian: `python3.14-venv`)
- Node.js **22.13+**, **24.3+**, **26.x**, or **≥27** (Expo SDK 58 engine range)
- npm (bundled), Git, a browser; optional Android phone with Expo Go SDK 58

### 9.1 Backend

```bash
cd backend
python3.14 -m venv venv
source venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip check
cp .env.example .env          # optional: mock AI works without editing it
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

`--host 0.0.0.0` listens on all interfaces so a phone on the same Wi-Fi can
connect. The Uvicorn default (`127.0.0.1`) is local-only and breaks physical
device testing. Use `--host 127.0.0.1` only if you deliberately want
localhost-only (emulator, `adb reverse`, or Expo web).

Health check: <http://localhost:8000/api/health>
API docs: <http://localhost:8000/docs>

**Firewall (UFW), LAN-restricted:**

```bash
# Replace 192.168.1.0/24 with YOUR subnet (e.g. 10.0.0.0/24, 192.168.0.0/24)
sudo ufw allow from 192.168.1.0/24 to any port 8000 proto tcp
sudo ufw status
```

Find your subnet with `ip -4 addr show scope global` (the `/24` next to
`inet`) or from your router's DHCP settings. Remove the rule with:

```bash
sudo ufw delete allow from 192.168.1.0/24 to any port 8000 proto tcp
```

Never expose this unauthenticated API to the public internet.

### 9.2 Web app

```bash
cd frontend
npm ci                        # both apps commit package-lock.json
cp .env.example .env.local    # optional; defaults to http://localhost:8000
npm run dev                   # http://localhost:5173
```

Production build + preview:

```bash
npm run build                 # tsc -b && vite build -> frontend/dist/
npm run preview               # http://localhost:4173
```

### 9.3 Mobile app

```bash
cd mobile
npm ci
cp .env.example .env.local    # then set EXPO_PUBLIC_API_URL (it ships empty)
npx expo start                # scan the QR code with Expo Go
```

`EXPO_PUBLIC_API_URL` is **required** for native builds. There is deliberately
no `localhost` default because on a phone `localhost` is the phone itself. If
missing, the app shows a configuration message instead of a vague network
error. Restart with `npx expo start --clear` after changing it.

| Where the app runs | `EXPO_PUBLIC_API_URL` |
|---|---|
| Physical Android phone (same Wi-Fi) | `http://<your-computer-LAN-IP>:8000` |
| Android emulator | `http://10.0.2.2:8000` |
| USB device with port forwarding | `http://localhost:8000` (after `adb reverse tcp:8000 tcp:8000`) |
| Expo web | `http://localhost:8000` |

Get the LAN IP:

```bash
hostname -I | awk '{print $1}'       # Linux
ipconfig getifaddr en0               # macOS Wi-Fi
```

Use a private-range address (`192.168.x.x`, `10.x.x.x`, `172.16–172.31.x.x`),
then verify from the phone's browser:
`http://<LAN-IP>:8000/api/health`.

### 9.4 Run everything (three terminals)

```bash
# Terminal 1 — backend (LAN-accessible)
cd ClassBreak/backend && source venv/bin/activate
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

# Terminal 2 — web
cd ClassBreak/frontend && npm run dev

# Terminal 3 — mobile
cd ClassBreak/mobile && npx expo start
```

Ports: backend `8000`, web dev `5173`, web preview `4173`, Expo/Metro `8081`.

## 10. Setup — Windows (PowerShell)

Prerequisites are the same, except Python is installed with the official
installer (`py -3.14`). All commands run from the repository root unless noted.

### 10.1 Backend

```powershell
cd backend
py -3.14 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python -m pip check

Copy-Item .env.example .env   # optional
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

If PowerShell blocks activation:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

…or call the executable directly:

```powershell
.\venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
```

### 10.2 Windows Firewall

Allow **only your LAN subnet**, not the whole internet. Run PowerShell as
Administrator and substitute your subnet:

```powershell
New-NetFirewallRule -DisplayName "ClassBreak dev (LAN)" -Direction Inbound `
  -Protocol TCP -LocalPort 8000 -RemoteAddress 192.168.1.0/24 -Action Allow
```

Check it:

```powershell
Get-NetFirewallRule -DisplayName "ClassBreak dev (LAN)"
```

Find your IP/subnet with `ipconfig` (IPv4 Address + Subnet Mask). Remove the
rule with `Remove-NetFirewallRule -DisplayName "ClassBreak dev (LAN)"`.

### 10.3 Web and mobile

```powershell
cd frontend
npm ci
Copy-Item .env.example .env.local   # optional
npm run dev

cd ..\mobile
npm ci
Copy-Item .env.example .env.local   # then set EXPO_PUBLIC_API_URL
npx expo start
```

For a physical phone, use your PC's LAN IP in `mobile\.env.local` and bind the
backend to `0.0.0.0` as shown. For the emulator use `http://10.0.2.2:8000`.

### 10.4 Windows caveats (honest status)

- The Python 3.14 install was executed on **Linux x86_64 only**. Windows
  support is **inferred** from cp314/abi3 wheel availability for every pinned
  distribution and from Uvicorn's `uvloop` platform marker (it is skipped on
  Windows). It has not been run on a Windows machine in this repo.
- `npm ci`, Vite, and Expo are cross-platform, but no Windows run of the
  frontend/mobile apps is recorded here either.
- If activation is blocked, use the direct `venv\Scripts\python.exe` form.
- Do not reuse a virtual environment created with another Python version.

  typecheck **and** `npx expo export --platform web`.

## 14. Security, privacy, and design decisions

### Deliberate design

- **Guest-first, local-first.** No accounts, no sessions, no server-side user
  data. This is a product decision, not an unfinished feature.
- **Server-side AI credentials only.** Clients never receive a key.
- **Stateless backend.** Nothing is retained between requests.
- **Persistent rate limiting as the cost control.** AI calls cost money; all
  AI routes stay limited.
- **Honest citations.** Fetched vs. model-supplied references are labeled
  differently; no pretend fact-checking.
- **PWA caches static assets only.** API responses are never cached.

### Residual risks (say these out loud in a review)

- The API is **unauthenticated**; rate limiting is in-memory, per-process, and
  resets on restart. A public deployment needs a gateway/auth story.
- The body-size guard checks `Content-Length` only; chunked bodies are not
  covered.
- Prompt injection is possible because user topics/interests/history are
  interpolated into prompts. System prompts instruct grounding, but that is not
  a security boundary.
- AI output can be wrong or incomplete. The UI labels mock/unverified content,
  but it is not authoritative.
- No HTTPS/production deployment is included. Local `http://` is for
  development; production needs HTTPS and a correct CORS origin list.
- Secrets management is just environment variables.

## 15. Known gaps and technical debt

Functional:

- Web quiz attempts store `answers: []`; score/questions/timestamp are saved.
- Mock lessons are the same cocktail-party fixture retitled for other topics.
- Mobile has no Settings/preferences, no feed personalization, no related-topic
  chips, and no feed history.
- Gemini thinking tokens count toward `MAX_RESPONSE_TOKENS`; long lessons may
  need a higher output budget.
- `MAX_PROMPT_LENGTH` is only applied to the lesson topic.
- Primary Wikipedia extracts are not truncated before prompting; long articles
  can inflate prompt size/cost.
- A new Gemini client is constructed per request.
- Web `preferences.theme` is stored but unused; theming follows the OS.
- Mobile tab bar depends on an unstable Expo API.

Maintenance:

- No frontend automated tests; no mobile component/integration tests.
- No CI pipeline; all checks are manual.
- No real-device verification for PWA or mobile.
- No data export/backup/migration; Dexie schema v1 and fixed AsyncStorage keys.
- Windows and macOS runs are not executed/recorded.

Do **not** "fix" by assumption: adding PostgreSQL/auth, changing AsyncStorage
keys or the Dexie schema, bumping Expo major versions, or rewriting the
provider interface all require an explicit decision.

## 16. Troubleshooting quick reference

| Symptom | Fix |
|---|---|
| `python3.14 -m venv` fails (`ensurepip`) | Install `python3.14-venv` (Debian/Kubuntu) |
| `pip install` tries to build pydantic-core with Rust | You are on the wrong Pydantic/Python combo; use Python 3.14 + `pydantic==2.12.5` |
| Port 8000 busy | `lsof -i :8000` / `netstat -ano \| findstr :8000`; stop it or change ports and update both client URLs |
| CORS error in the browser | Add the exact origin (scheme+host+port) to `CORS_ORIGINS`, restart backend |
| Phone cannot reach backend | Bind `0.0.0.0`, use the LAN IP (not localhost), allow TCP 8000 from the LAN only, avoid client-isolated Wi-Fi |
| Emulator cannot reach backend | Use `http://10.0.2.2:8000` |
| App says "Backend URL is not configured" | `mobile/.env.local` missing or still empty; set it and restart Expo with `--clear` |
| Expo Go says project incompatible | Phone's Expo Go is not SDK 58; update it, run `npx expo-doctor` |
| `npm ci` fails / tarball errors | `rm -rf node_modules && npm ci`, `npm cache verify`; never use `--force`/`--legacy-peer-deps` |
| `npm ci` says lockfile out of sync | Regenerate deliberately with `npm install`; don't work around it |
| Web build reports a phantom unused symbol | Delete stale `tsconfig*.tsbuildinfo`, rebuild |
| Mobile type error in `app-tabs.web.tsx` after upgrading Expo/RN | Re-evaluate the documented ref cast; verify with typecheck + web export |

## 17. Suggested demo flow (5–7 minutes)

1. **Hook (20 s).** "You have five minutes. ClassBreak gives you one
   interesting thing to learn — and makes it stick."
2. **Discover (45 s).** Show the feed, pull to refresh, tap a topic.
3. **Lesson (90 s).** Point out the structure: summary, sections, key points,
   examples, takeaways. Scroll to sources and explain Wikipedia grounding.
4. **Tutor (60 s).** Ask a follow-up, show the grounded answer and suggestion
   chips.
5. **Quiz (60 s).** Answer one multiple-choice and one open-ended question; show
   explanations.
6. **Remember (45 s).** Save the lesson, open Review, advance the schedule.
7. **Offline/privacy (45 s).** Turn off Wi-Fi, reopen the saved lesson; explain
   local-first storage and that the server keeps nothing.
8. **Close (30 s).** "Guest-first, source-grounded, offline-capable — and it
   runs on the phone in your pocket."

Demo tips:

- Run in **mock mode** for a deterministic demo (no key, no cost); say clearly
  that content is mock.
- Or use a real key for quality, but acknowledge live Gemini API calls
  (free-tier quota applies) and review the output first.
- If the phone is unavailable, demo the **web app** (same loop) and mention the
  Expo build was verified by export but not on hardware.

## 18. Likely questions and honest answers

**Is this production-ready?**
It is a verified local/dev application, not a production deployment. Backend
tests, web build, mobile types/lint/tests/doctor/export all pass, but there is
no auth, no HTTPS, no CI, and no real-device run recorded.

**Why no accounts/database?**
Privacy and friction: learning data is personal and small, so it lives on the
device. A server-side user store would add cost, compliance surface, and a
single point of failure for no product benefit at this stage.

**What happens without a Gemini key?**
The backend automatically uses a mock provider, so every flow still works
end-to-end. It is clearly labeled mock content and is not a quality demo.

**How do you stop AI cost abuse?**
Per-IP rate limits (30/min for AI routes, 60/min for source search) and a
request-size guard. For a public deployment, put it behind an authenticated
gateway with shared limits — the current limiter is per-process.

**Are citations trustworthy?**
They are structurally validated and labeled. Fetched Wikipedia URLs are marked
`wikipedia`; model-supplied URLs are marked `provided` (unverified). There is
no semantic fact-checking.

**Can it work offline?**
Saved lessons are readable offline on both clients. Discovery, quizzes, tutor,
and source search require the backend. The PWA caches only the app shell.

**Why two clients?**
The web app is the fast, mobile-first PWA; the Expo app is the Android-first
native experience with the same contract and backend. They share behavior
deliberately but are not a shared codebase. Mobile has fewer features today.

**What would you build next?**
Real on-device QA, a small frontend test suite, CI, data export/import, feed
personalization on mobile, semantic grounding checks, and a production
auth/gateway story — in that order. None of these should be added without an
explicit decision.
